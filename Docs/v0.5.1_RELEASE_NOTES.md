# OpenMarked 0.5.1

OpenMarked 0.5.1 is a performance stabilization release for very large Markdown notes, especially documents with many local images.

## Highlights

- Moves Markdown document loading, rendering, postprocessing, preview HTML preparation, and inspection report generation off the main actor.
- Adds cancellation and stale-render suppression so rapid live-preview saves cannot publish obsolete previews.
- Caches built-in preview themes and status-bar statistics so scrolling does not repeatedly read theme CSS or recalculate full-document word counts.
- Optimizes current-section tracking with cached heading offsets, throttled WebView updates, and automatic large-document fallbacks.
- Adds preview-only image optimization with lazy/async image hints, local intrinsic dimensions, metadata caching, and oversized raster downsampling while preserving originals for export and print.
- Scales live preview image watching from per-file watchers to folder-filtered or manual reload modes for image-heavy notes.
- Stores document inspection reports after render, uses lazy inspector lists, and caps very large link, asset, diagnostic, and section lists until Show All is selected.
- Adds Settings controls for Performance Mode, Current Section tracking, and Referenced Images reload behavior.
- Fixes an after-scroll SwiftUI layout feedback loop by making window resolution, active-window publishing, and app chrome background writes idempotent.
- Adds generated large-image fixtures, performance smoke timings, scroll-audit tooling, and async open/stale-render test coverage.

## Performance Audit

The final audit used the packaged `dist/OpenMarked-0.5.1/OpenMarked.app` with the generated large-image fixture:

- Scroll-time CPU peak: `7.5%`
- Post-settle CPU: `0.0%`
- Post-settle RSS: about `171 MB`
- Repeated status statistics hot-stack matches: `0`
- Repeated preview theme CSS hot-stack matches: `0`

The post-settle stack sample shows the main thread sleeping in the normal AppKit run loop.

## Known Limitations

- Render-changing edits still reload the full WebView document; DOM patching is deferred.
- Preview image downsampling is preview-only. HTML/PDF export and print continue to use original local assets by default.
- Opening the same source file more than once may create duplicate tabs.
- Exact native tab order and tab group topology are not restored; session restore reopens the saved document list and groups documents into tabs where possible.
